# 2026-09-24 — v0.2.0: what was read in the five applications, and what was not

What this proves: which parts of ADR 0012's release oracle were done on the bytes v0.2.0 ships,
which were not, and what the maintainer decided about the gap. **The release goes ahead with two
applications not fully read.** ADR 0012 asks for all five before every release; on 2026-09-24 the
maintainer decided to cut v0.2.0 first and record the gap here rather than change the rule. Each
reading still owed will be recorded on its own when it is done.

The bytes: `python3 tools/oracle_set.py` from `main` at `7f9a8e4`, every file byte for byte its
golden in `tests/golden/`, plus two documents built by hand with `--thai-language` and
`--force-cs-whole-doc` from `tests/fixtures/thesis/thesis.md`. Rebuilt on 2026-09-23 and compared:
all 21 files of the set and both extras identical. The release commit changes versions and
documentation only; the goldens do not move. Content synthetic (ADR 0025 §10). Readings were taken
from the maintainer's screenshots; application versions were not recorded in them.

## 2. LibreOffice Writer — what the one document showed

- **Every Thai word underlined, status bar reading Hindi.** The default document does not name its
  complex-script language (ADR 0038), and LibreOffice does not take one from the machine: it uses
  its own default for complex text layout, which on this English installation was Hindi. Setting
  it to Thai under Tools → Options → Languages and Locales → General removed every underline.
  This is not specific to `--auto-numbering`, so it is expected of every default document; that
  is **not yet measured** on `sample-text`, and whether `--thai-language` settles it is not
  measured either. Written into `limits.md` §3.
- A second opening on 2026-09-24 showed no underlines because the setting made the day before was
  still in force, although *For the current document only* had been ticked. That reading says
  nothing about the underline.
- **Heading numbers in Thai digits drawn as 1, 2, 3; captions as `ตารางที่ บทนำ-ก`**, the
  chapter's title in place of its number, no restart at a new chapter, and the Thai-digit counter
  drawn as Thai letters. The record behind ADR 0035 and 0036 was not kept on `main`; this is the
  measurement that stands behind them now.
- **LibreOffice cannot carry a chapter number through .docx for its own captions either.** A
  document made by hand in LibreOffice — Tools → Heading Numbering, Insert → Caption with the
  chapter level 1 and `-` as separator — shows `ตารางที่ 1-1`, `2-1`, `3-1` correctly as .odt, where
  the chapter level belongs to the whole sequence
  (`<text:sequence-decl text:display-outline-level="1" text:separation-character="-">`). Saved as
  Word 2010–365 .docx it writes each caption as one `SEQ ตารางที่ \* ARABIC` field whose cached
  result is `1-1`; opened again and updated, the caption reads `ตารางที่ 1`. So the application
  has no field to meet `STYLEREF`, and nothing this project writes differently would reach it —
  a limitation, not a defect ([rules](../rules.md); `limits.md` §7).
- Thai inside a code block is small beside Consolas, as `limits.md` §8 says.

## 3. Model equivalence

Claude Code 2.1.281 headless (`claude -p`, project settings only, tools limited to `python3`,
`node`, Read, Write, Edit, Skill, Glob), each case a directory outside any repository holding the
archive from `tools/package_skill.py`. Models: `claude-haiku-4-5-20251001`, `claude-sonnet-5`,
`claude-opus-5-5`.

| request | Haiku | Sonnet | Opus |
|---|---|---|---|
| *sample* — `sample.md` on the defaults | golden `sample-default` | golden | golden |
| *thesis* — `thesis.md`, numbers on headings, page number bottom centre | **1 of 3 golden**; two wrote `--auto-numbering` in place of `--heading-numbers` | golden `thesis-text` | golden |

The first *sample* round had no `pixel.png` beside the Markdown — a fault of the harness, not the
skill; all three models refused to build and said which line named the missing image.

A mismatch means `SKILL.md` is unclear (ADR 0012). It named `--auto-numbering` and never
`--heading-numbers`, so a model that did not open `references/settings.md` reached for the one it
saw. `SKILL.md` now says numbers on headings are `--heading-numbers` and `--auto-numbering` is
added *as well*. On that text Haiku, five runs: **four golden**; one added `--toc`, which was not
asked for. `SKILL.md` already says to add a flag only for what the user asked; that run did not.
Sonnet and Opus were not run again on the new text.
